## 1. 设计目标

为一个企业内多人协作的知识库系统建模，覆盖以下需求：

| 需求 | ODDM 对应能力 |
| --- | --- |
| 多用户（员工 / 部门） | `User` 类 + `Organization` 类 |
| 文档分层（空间 → 文档 → 块） | 树状拓扑 + 路径寻址 |
| 富文本块（标题 / 段落 / 列表 / 代码 / 引用） | 块对象 + `ref` 引用 |
| 多人编辑与版本历史 | `version` + `migrate` + `__updated_at__` |
| 评论、点赞、@ 提及 | 集合代理 + `ref(User)` |
| 标签与全文检索 | `tag: refs(Tag)` + `Query DSL` |
| 权限（公开 / 部门内 / 仅作者 / 指定用户） | `permission: int` 位掩码 |
| AI 助手消费 | `introspect()` + APL |

## 2. 类图（ODL 视角）

```
Root
└── Organization['acme']                   组织
    ├── User['alice']                      员工（继承 User 基类）
    │   ├── Post['doc-1']                  文档
    │   │   ├── Block['b1']                块
    │   │   ├── Block['b2']
    │   │   └── Comment['c1']              评论
    │   └── Tag['tech']                    标签
    └── User['bob']                        员工
        └── Post['doc-2']
```

所有节点通过 ODL 路径寻址，例如：

- `Root.Organization['acme'].User['alice']` —— 组织内的 alice
- `Root.Organization['acme'].User['alice'].Post['doc-1'].Block['b2']` —— alice 文档 doc-1 的第 2 块

## 3. Schema 设计

### 3.1 基类 `User`

```js
client.defineClass('User', {
  name:      'string',     // 姓名
  email:     'string',     // 邮箱（唯一标识，物理 Key）
  role:      'string',     // admin / editor / viewer
  joined_at: 'datetime',
  avatar:    'string',
});
```

### 3.2 `Organization`（组织 / 部门）

```js
client.defineClass('Organization', {
  name:        'string',
  description: 'string',
  plan:        'string',   // free / pro / enterprise
  created_at:  'datetime',
});
```

### 3.3 `Post`（文档）

```js
client.defineClass('Post', {
  title:      'string',
  body:       'json',      // 富文本 AST（TipTap / ProseMirror 兼容）
  status:     'string',    // draft / published / archived
  tags:       'refs(Tag)',
  author:     'ref(User)',
  org:        'ref(Organization)',
  permission: 'int',       // 位掩码：1=公开 2=组织内 4=指定人
  created_at: 'datetime',
  updated_at: 'datetime',
  views:      'int',
});
```

### 3.4 `Block`（块，作为文档的子节点）

```js
client.defineClass('Block', {
  type:    'string',       // heading / paragraph / list / code / quote / image
  content: 'json',
  order:   'int',
  post:    'ref(Post)',
  author:  'ref(User)',
});
```

### 3.5 `Comment`（评论）

```js
client.defineClass('Comment', {
  body:     'string',
  author:   'ref(User)',
  target:   'ref(Post)',   // 或 ref(Block) 引用块级评论
  parent:   'ref(Comment)',// 二级评论
  created_at: 'datetime',
});
```

### 3.6 `Tag`（标签）

```js
client.defineClass('Tag', {
  name:  'string',
  color: 'string',
  org:   'ref(Organization)',
});
```

### 3.7 权限位掩码（业务常量，不入 ODDM）

```js
const PERM = {
  PUBLIC:   1,
  ORG:      2,
  PRIVATE:  4,
  LIST:     8,  // 指定白名单
};
```

## 4. 关键操作示例

### 4.1 创建组织与用户

```js
client.createChild('Organization', 'acme', 'User', 'alice', {
  name: 'Alice', email: 'alice@acme.com', role: 'editor',
});
client.createChild('Organization', 'acme', 'User', 'bob', {
  name: 'Bob', email: 'bob@acme.com', role: 'viewer',
});
```

### 4.2 创建文档（带块）

```js
const postPath = "Root.Organization['acme'].User['alice'].Post['doc-1']";
client.put(postPath, {
  title: 'ODDM 设计方案',
  body:  { type: 'doc', content: [] }, // TipTap 空文档
  status: 'draft',
  author: 'User/alice',
  org:    'Organization/acme',
  permission: PERM.ORG,
  tags:   [],
});

// 一次性挂多个块
const blocks = [
  { type: 'heading',   content: { level: 1, text: '引言' },     order: 0 },
  { type: 'paragraph', content: { text: 'ODDM 是对象数据库' }, order: 1 },
  { type: 'code',      content: { lang: 'js', code: '...' },    order: 2 },
];
for (const b of blocks) {
  client.createChild('User', 'alice', 'Block', `b${b.order}`, {
    ...b, post: 'Post/doc-1', author: 'User/alice',
  });
}
```

### 4.3 添加评论（引用 ref + refs）

```js
client.put("Root.Organization['acme'].User['bob'].Comment['c1']", {
  body: '写得真好',
  author: 'User/bob',
  target: 'Post/doc-1',
  parent: null,
});
```

### 4.4 查询 DSL

```js
// 找 alice 的所有已发布文档，按更新时间倒序
client.Post
  .where({ status: 'published', author: 'User/alice' })
  .order({ updated_at: 'desc' })
  .limit(10);

// 全文模糊（SQLite LIKE，attrs.text 是 string 类型）
client.Post.where({
  title: { $like: '%ODDM%' },
}).toArray();

// 多条件组合（AND）
client.Post.where({
  status: 'published',
  views:  { $gte: 100 },
  tags:   'Tag/tech',  // 单一 ref 命中
}).count();

// 迭代
for (const p of client.Post.where({ status: 'published' })) {
  console.log(p.title);
}
```

### 4.5 集合视图（固化常用查询）

```js
// alice 名下文档集（生成 SQL view，可被 queryObjects 直接查询）
client.helper.createCollectionView('User', 'alice', 'Post');
client.views.queryObjects('User_alice_Posts').map(p => p.title);

// 整组织文档集
client.helper.createCollectionView('Organization', 'acme', 'Post');
```

### 4.6 版本演进

```js
// v1.0 Post 没有 pinned 字段，v2.0 加入
client.defineClass('Post', { /* ... */ }, '1.0');
client.defineClass('Post', { /* ... + pinned: 'boolean' */ }, '2.0');
const n = client.migrate('Post', '1.0', '2.0', (ent) => ({
  ...ent,
  pinned: false,  // 新字段默认值
}));
console.log(`迁移 ${n} 条文档到 V2.0`);
```

### 4.7 树形导航

```js
const helper = client.dbHelper;
helper.children('Organization/acme');           // ['User/alice', 'User/bob']
helper.children('User/alice');                  // ['Post/doc-1']
helper.descendants('Organization/acme');        // 整棵子树（递归 CTE）
helper.ancestors('Block/b2');                   // [User/alice, Organization/acme]
helper.canonicalPath('Block/b2');               // 反解完整 ODL 路径
```

### 4.8 AI 消费入口

```js
// 给 AI Agent 的全文快照（自省 schema + 树形结构 + 统计）
const snapshot = client.introspect({ treeDepth: 3, includeSample: true });
// 写入 docs/introspect.json 喂给 Agent

// 单类详情：每个属性支持哪些比较运算
client.introspectClass('Post');
```

## 5. 权限与多租户

### 5.1 路径级租户隔离

ODL 路径天然含组织边界：`Root.Organization['acme']` 之下的所有对象逻辑上属于 acme。
业务代码只需在查询前加 `where({ org: 'Organization/acme' })`，
无需额外的多租户中间表。

### 5.2 文档级权限

`Post.permission` 是位掩码字段，业务层在 `get` 之后做二次校验：

```js
function canRead(post, user) {
  const p = post.permission;
  if (p & PERM.PUBLIC) return true;
  if (p & PERM.ORG && post.org === user.org_path) return true;
  if (p & PERM.PRIVATE && post.author === user.path) return true;
  return false;
}
```

### 5.3 写入控制

ODDM 本身不做权限拦截，由业务层在 `put` / `destroy` 前校验。
v0.4.0 计划在 Helper 增加 `withGuard(...)` 装饰器模式。

## 6. 性能与扩展

| 场景 | 当前实现 | 后续规划 |
| --- | --- | --- |
| 文档数 ≤ 10 万 | 单库 SQLite 完全胜任 | — |
| 文档数 10–100 万 | 加 `(attribute_name, v_xxx)` 复合索引（v0.2.0 已建） | 物化视图 |
| 文档数 > 100 万 | — | 分库分片（按 Organization 切分） |
| 富文本检索 | 内存 LIKE / 正则 | 接入 SQLite FTS5 |
| 实时协同 | — | OT / CRDT 层（v0.5+） |

## 7. 与传统方案对比

| 维度 | 传统 RDB | ODDM |
| --- | --- | --- |
| Schema 演进 | ALTER TABLE，迁移脚本 | `defineClass(... '2.0')` + `migrate(...)`，数据可编程 |
| 多租户 | 额外租户表 / RLS | 路径自带组织边界 |
| 引用查询 | JOIN + 索引 | `ref` / `refs` 直接包装，懒加载 |
| AI 友好 | 需写 schema 描述文件 | `introspect()` 一次给出完整画像 |
| 路径即 URL | 自己拼 | `helper.canonicalPath()` 直接给 |
